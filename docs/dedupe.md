# Finite dedupe

`loupe dedupe` reads a finite catalog, evaluates every unordered pair with a Noul, and forms connected components from accepted edges. It emits one representative per component only after EOF and all required decisions succeed. A bridge can merge records whose direct pair answer was no. [Streaming window modes](streaming-dedupe.md) instead use bounded greedy keep-first matching against retained representatives.

```sh
loupe --profile server dedupe < incidents.txt
loupe --profile server dedupe 'Do these records describe the same incident?' incidents.txt --keep longest --json
loupe --profile server dedupe -f pair-question.toml records.jsonl -I jsonl --failed run.jsonl > representatives.jsonl
loupe --profile server dedupe -f pair-question.toml records.jsonl -I jsonl --resume run.jsonl >> representatives.jsonl
loupe --profile server dedupe --files notes-a.txt notes-b.txt --dry-run
```

With no operands the default question asks whether the two records convey duplicate meaning about the same underlying item/event. With positional operands, the first is the question and the rest are input files. `-p NAME` or `-f FILE` supplies a trusted Noul rubric, leaving all operands as input files. `--files` uses the default question and treats every operand as a whole file. No file operands means stdin. One `-` stdin operand is allowed. Ordinary line/paragraph/record/whole/NUL/JSONL/CSV/TSV readers, field projections, selected columns, context and preset permissions apply.

Each pair is a separate request whose state contains `left` and `right`, each with a stable source `id` and the original comparison `record`. IDs are `L<n>` for lines, `R<n>` for records, `F<n>` for whole files and `U<n>` for whole/NUL units. Indices count original input units, including skipped blanks, and continue across files. `--field` changes the echoed subject while the full structured state still reaches the model. Context accompanies each unit and can affect the pair decision. The primary question and declared signal heads decide jointly; different pairs have separate requests. Normal context/templates, exact complete-schema preflight, attempt budgets, retries, deadlines and fresh cache discovery apply.

The primary true probability is assessed using the normal threshold/margin policy. Threshold equality is yes; distance strictly below margin is uncertain. Certain yes adds an edge; certain no adds none. Default uncertain/drop adds none, keep adds a provisional edge, stderr adds none with a diagnostic, and fail exits 3. `--why` requires declared signals and reports their separate local assessments. Choice/Score rubrics and their confidence/gap flags are invalid. Classification calibration pins are refused because they do not establish pair calibration. Explicit full model requirements need fresh discovery.

`--on-uncertain fallback --fallback COMMAND` resolves an uncertain pair Noul with the shared trusted CLI/config executor. The command receives the complete compact pair-state JSON plus LF on stdin, including both comparison records and stable IDs; original input terminators remain in representative output. Typed-question/raw-answer environment metadata is unchanged. Print `yes` to add an edge or `no` to omit it. Default nonzero/timeout/invalid-output failures warn and omit the edge; `--on-fallback-error fail` exits 69 with no representatives. Per-child and overall deadlines apply. External costs remain separate from the model-token budget.

Merge links retain the raw model `assessment` and `answer`, adding a separate external `decision` with `source:"fallback"`/`confidence:null` and a `fallback` process outcome when applicable. `--why` also separates raw assessment from the external decision. Each pair's completed fallback outcome is journaled after its raw evaluation and before graph changes. Successful and failed saved outcomes replay without another child or inference, with command/timeout/failure policy pinned. Once a fatal result arrives, already submitted model results can still be saved, but later fallbacks are skipped. A crash between a child effect and its synced outcome can repeat that child. See [fallback.md](fallback.md).

`--keep first|last|longest` defaults to first. First/last use original source order. Longest uses Unicode scalar length of rendered comparison state, excluding neighbor context and whole-file path. Structured records use the complete comparison state, including selected columns, even when a field projection changes the echoed subject. Length ties choose the earliest member. Cluster IDs are the smallest source index in each component. Representatives are emitted in representative source order, which can differ from cluster-ID order.

Plain output preserves the representative's original bytes and delimiters; CSV/TSV input emits its original header once. All input files must have identical headers. Annotate prefixes `cluster=<id> members=<count>` plus a tab. TSV output has representative index, member count, comma-separated source indices and escaped text. JSONL emits `index`, original `unit`, `cluster`, `keep`, member original subjects/locations, representative `location`, and accepted merge `links`. Links retain endpoint indices, the unchanged primary answer, local assessment, model/cache identity, exact input count and requested signals. They form a spanning witness, rather than containing every accepted redundant edge. A requested journal preserves every pair's complete raw evaluation, including negative pairs.

An empty catalog exits 1; a nonempty successful catalog exits 0. Empty/singleton catalogs require no inference. Fatal input/preflight/inference/budget/uncertainty failures emit no representatives. Splitting, focus, truncation, non-unit packing, uncertain-file and keep-going policies are exit 64: partial pair coverage does not establish completed clusters. `--dry-run` emits complete pair requests/counts in pair order and performs no inference or recovery writes. `--max-pairs N` refuses a catalog exceeding N pairs before inference, with the exact required count.

Summary `units` counts assessed pairs, including replayed decisions. Attempts/usage/latency count submitted inference; replayed journal evaluations consume no new budget. Output is a count of final representatives, not the pair counter. The tokenizer loads in a background task after EOF; empty/singleton catalogs skip it. SIGTERM/SIGINT handlers register before the work future is polled.

Memory holds the complete finite catalog, its raw bytes/context/provenance, union-find state, at most one concurrency-sized batch of pair plans/responses, and at most N minus the component count merge witnesses. It does not retain all pair results in RAM. There are N(N−1)/2 model requests, so time, token cost and requested journal storage grow quadratically. Pair-local states can copy large records within the bounded batch. There is no default pair cap or lexical blocking that silently omits a transitive bridge. Use `--max-pairs`, `--budget` and `--deadline` to bound work. Use the bounded [streaming window modes](streaming-dedupe.md) for long or infinite input.

`--failed FILE` records byte fingerprints for the complete catalog, effective questions/policy/output/reader/model/encoder identity, generated pair admissions/plans, full raw evaluations and dispositions. Pair admissions are generated work IDs (`left-index:right-index`), not source byte spans. Original physical provenance remains in the source catalog and output. `--resume FILE` rereads and validates all source bytes before new inference/output, reuses completed pair responses and reconstructs the graph. Changed delimiters, projected-away fields, questions, policy or identities are refused. A saved uncertain fatal response replays the same failure without inference, and a fully finished resume emits nothing. Deadlines and signals remain responsive while stdin is idle.

Representative checkpoints follow each stdout flush and suppress acknowledged rows and repeated CSV headers on clean resume. A crash between external stdout delivery and its acknowledgement can duplicate that row, as with the general stdout journal. This is not transactional output delivery. Input/stdout aliases and competing journal writers follow the existing store protections. Legacy server lacks authoritative full identity discovery, so cache remains disabled and same-weight identity across separate runs is unqualified.

Functional qualification uses real server distributions, mathematical graph tests, real readers/processes and filesystem journals. Held-out duplicate precision/recall, full live identity/cache, refreshed native release artifacts and other platform runtime checks remain open.

`--ensemble` expands named Noul variants from the source rubric; see [the example](../examples/dedupe-ensemble.toml). Mean probabilities and the agreement gate decide graph edges, using the same uncertainty/fallback policy. Accepted merge links retain raw `answer`/`assessment`, add the full `ensemble` report and a separate derived/external `decision`. Every head enters exact limits and receives the same context. Changing the agreement gate refuses journal replay. [Streaming mode](streaming-dedupe.md) applies the same mean decision to bounded keep-first suppression and retains reports in pair checkpoints.
