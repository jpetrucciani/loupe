# Evaluation runs

[Document selection suites](selection-evaluation.md) run native find/pick/independent/extract pipelines with separate retrieval, absence/certainty, source-span and normalization checks, plus bracket presence calibration. They share this runner's discovery, attempt budget, fixed partitions and uncached phase contracts.

[Catalog join suites](join-evaluation.md) run through `eval --suite join`, with separate blocking recall, full/retained pair quality, cardinality assignments and complete uncached join pipelines. Join suites use their own catalog label shape and run separately from classification/parity suites.

The runner consumes pinned suite manifests or an explicitly versioned labeled JSONL file. It selects fixed held-out test IDs by default. Explicit comparisons retain paired decision matrices, and packing/combine/focus sweeps use calibration data. The separate [calibrate command](calibration.md) fits a concrete policy or selects and publishes a winning execution view. [`--baseline FILE`](baselines.md) evaluates held-out absolute/regression gates from a manually ratified, identity-pinned report; production ratification and positive live identity qualification remain open.

    loupe --config examples/config.toml --profile server eval --suite presets/severity --json
    loupe --config examples/config.toml --profile server eval --labels alerts.jsonl -p severity --dataset-revision reviewed-v1 --init-splits --report private-reports

The positional dataset and --labels are equivalent. Direct JSONL requires a trusted preset and a nonempty dataset revision. It uses seed 42 with a 50% calibration allocation and stores assignments beside the dataset as FILE.splits.json; --split-file can select another confined relative path. Cases still need unique IDs and the case format in [evaluation-suites.md](evaluation-suites.md). Document fixtures require a suite manifest with fixture pins.

--suite accepts a manifest, a directory containing suite.toml, or a name beneath --suites-dir, which defaults to evals/suites. Repeat it for several suites, or use --suite all to discover manifests recursively. Recursive discovery skips symlinks. Suite IDs must be unique within a run. --init-splits explicitly creates missing assignments after case/preset/policy validation. Existing split files are validated against exact content/revision pins and deterministic IDs; they are never replaced. --partition calibrate and --partition captured select those separate partitions. Review-origin cases remain in captured and never enter test automatically.

Only selected case state is sent to the model. Labels, notes, review status and split IDs stay in the report. Case query/candidates fill trusted argument templates, while static and per-case reference context follows normal preset context encoding. A CLI argument cannot replace a labeled case's query/candidates. Physical JSONL line numbers, original byte ranges, base IDs, packed IDs and question insertion order are preserved. Contiguous cases share a group only when effective questions, context, policy and view settings match.

--pack, --split --combine, --focus, --truncate and --truncate-field reuse the classification planner. Structured cases never split/focus and can truncate only an explicitly selected field. Every report retains original state and the actual request, response, exact/estimated counts, selected view/chunk ranges and combine provenance. Whole-document overflow without an explicit view remains exit 65.

Each record labels its request_role. For split results, request/counts describe the original unsent input; the provenance contains all submitted chunk requests/counts and raw responses, and derived usage sums those responses. For live focus, request/counts describe the final selected-evidence request; provenance additionally retains every relevance request's counts/response, and derived usage includes both phases. An offline focus record describes the original input and conditional plan. Truncation and direct inference retain their actual evaluated request/counts. Suite/run token ledgers count submissions without multiplying a shared joint request by its number of cases.

Live evaluation requires fresh authoritative full model/encoder discovery. A server that exposes only a model alias fails with exit 69 before inference. --allow-unverified permits provisional diagnostics, retaining the discovery failure and observed response aliases while keeping cache disabled. It cannot establish a full identity or a baseline. server now exposes the complete identities; default verified evaluation passes without diagnostic mode. --dry-run performs no discovery, credentials or inference and emits a plan with undefined inference latency and zero submitted usage.

    loupe --config examples/config.toml --profile server eval --labels alerts.jsonl -p severity --dataset-revision reviewed-v1 --init-splits --allow-unverified --strict --json

Full run identity includes discovered weights revision, dtype, quantization and server build; pinned local/server encoder identities; actual preset content/hash/version; effective questions/policy; packing and combine/view settings; and suite/data/split provenance. Responses must match fresh discovered identity. Even provisional runs reject a changed response model across phases. Saved parity references preserve exact request state, questions/order and encoder identity. A known different full reference identity is rejected pending explicit comparison support. Alias-only references are provisional and cannot establish cross-precision reference equivalence.

Each suite runs accuracy first, then --warmup N complete uncached passes (default one), then a separate uncached measured pass. --no-cache disables accuracy caching; --refresh refreshes eligible accuracy entries. Cache eligibility still requires fresh matching identities. Reports distinguish requested caching, actual hits, logical evaluations and submitted attempts. Warmup and latency backends disable cache regardless of accuracy mode.

Latency samples measure an entire completed packing-group pipeline, including encoding/planning, queue admission, retries and split/focus work. A unit batch is one group; a joint window is one group; halved windows or chunked/focused cases remain inside their original group's sample. Reported p50/p95 use exact nearest-rank samples. Throughput counts original completed units over phase wall time. These are pipeline timings, with declared scope and concurrency recorded. Warmup is excluded from the measured pass. Global GPU counters are not attributed to this run.

--budget covers verified clef-v1 input tokens across all accuracy, warmup and measured requests, charging every submitted retry and retaining unknown submitted usage as spent. Estimated profiles cannot claim the hard guarantee. --deadline bounds discovery and all phases together. A fatal phase stops the run and records the completed ordered accuracy prefix, usage and an incomplete status. Budget exhaustion is exit 4, overflow is 65, transport/deadline or identity failure is 69, authentication is 77. Token cost uses only explicitly configured prices and records unknown output cost.

--json prints the versioned evaluation report object. The default prints Markdown. --report DIR also creates a private, unique mode-0700 bundle with mode-0600 report.json, report.md and manifest.json. Descriptor-relative, exclusive NOFOLLOW writes prevent overwrites or redirection through a replacement root. The manifest is published atomically only after data files are synced and contains byte lengths and BLAKE3 hashes. A directory without a valid manifest, or with mismatching files, is an incomplete bundle. Crashes can leave unpublished bundles or a private pending link. Reports contain original data, labels and model responses and belong outside public source trees when inputs are private.

Classification metrics use actual accuracy-pass responses and [documented formulas](evaluation-metrics.md). Mixed rubrics get one report per field/options/policy signature; query text may vary and remains visible in individual records. Undefined values retain support and reason. Metrics declared by a manifest are checked for applicability. Gate declarations are retained without acceptance unless `--baseline FILE` supplies manually ratified floors and a verified complete held-out reference. Selection/retrieval command execution, positive live calibrated writes/acceptance and reviewed public seed sets remain unqualified.

## Comparisons and calibration sweeps

`--ensemble` evaluates the mean of a preset's original questions and named variants, with 100% agreement required by default or an explicit `--min-agreement`/preset gate. Generated heads stay in raw provenance but do not require extra labels. Agreement uncertainty persists across confidence coverage curves. `--compare standalone ensemble` measures both configurations over identical fixed cases and reports aggregate differences separately from `raw_primary_shift`, which compares the unaveraged original answers. The same model/local/server encoder identities must remain constant across that experiment. Each record's settings, schema and recomputed summaries identify its policy; saved comparisons reject inconsistent summaries. Scalar calibration and exact server parity do not accept ensemble expansion. See [ensemble grammar and proof boundaries](ensembles.md).

--compare LEFT RIGHT accepts published report bundle directories, profile:NAME or preset:NAME_OR_PATH. A report: prefix can make a bundle selector explicit. Live targets use the same --suite or labeled JSONL input and the normal config/global overrides. A preset target changes the effective rubric while preserving the original suite and fixed split identity. -p can override a suite preset as well as selecting an ad hoc preset. Explicit trusted paths let different preset versions coexist. A saved target can be paired with a live target; two saved targets need no dataset or preset arguments and perform no discovery, credential execution or inference.

    loupe eval --labels alerts.jsonl -p severity --dataset-revision reviewed-v1 --compare profile:local profile:jev --json
    loupe eval --suite presets/severity --compare preset:severity preset:severity-v2 --json
    loupe eval --compare baselines/release-a baselines/release-b --json

Saved inputs must be complete version-1 evaluator bundles with a valid publication manifest and matching byte lengths/BLAKE3 hashes for both report files. Regular descriptor-relative reads reject symlinks, FIFOs and unpublished or changed bundles. Plans, incomplete runs, partial case sets and invalid question/binding/policy metadata are rejected. Unverified saved reports require --allow-unverified and produce provisional comparisons. Historical tokens, timings and prices stay inside each saved variant; the outer ledger counts only new submissions by this command.

Comparisons require matching dataset/fixture pins, fixed split assignments, partition, complete case IDs, labels and capture provenance. Records can arrive in different orders; pairing uses IDs. Different suite IDs or preset versions can pair when those inputs match unambiguously. Duplicate identical suite provenance is rejected with a request to compare one suite at a time. Single-field scalar labels use a primary comparison field while retaining both original question IDs; mixed labels require matching field IDs. Types and declared label keys must match, while instructions/descriptions and decision policies may differ. A changed option set requires a separately designed comparison rather than pooling incompatible outcomes.

Each paired field reports a decision confusion matrix, changed case IDs, and micro-averaged maximum/mean probability difference. Uncertainty is its own typed outcome, distinct from a Choice option named uncertain. Score outcomes preserve the actual expected score. Both variants retain full raw request/response, identity, policy, provenance and metric reports; distributions or quantization identities are never averaged together. Explicit --compare permits different full reference/model identities; ordinary parity remains strict.

--sweep-pack unit,window:4,window:16, --sweep-combine any,noisy-or,mean and --sweep-focus 0,3 form a grid over the fixed calibrate partition. Explicit --partition test or captured is exit 64. Combine candidates imply text splitting. Focus zero means split/combine without focus; positive values run the selected-evidence pipeline and clear the inapplicable combine operation. Duplicate effective variants are measured once. Auto is not a measurement candidate. --pack auto honors a preset's concrete policy.pack and otherwise uses unit. `calibrate --sweep-* --write` fits feasible policies and publishes the winner by accepted support, correctness and uncached throughput; eval only measures and compares. Types, structured-input rules and view limits are validated for every candidate before discovery or split publication. Test/review cases never enter the calibration grid.

`--question-id-source lines|records|files|units` chooses the source family for window head IDs and state keys. The default is records (`R<n>`), or the saved family of a calibrated policy. Original physical case indices remain stable. Set lines (`L<n>`) when measuring ordinary line filters; the family enters the calibration view pin because IDs enter the prompt. Unit/whole requests retain their original head IDs. Saved-report-only comparisons reject this live override. Ordinary evaluation restores a calibrated preset's saved focus, split/truncation and chunk defaults unless explicit view controls are provided; explicit recalibration may change them.

    loupe eval --suite presets/severity --sweep-pack unit,window:4,window:16 --json
    loupe eval --suite long-input --sweep-combine any,noisy-or,mean --sweep-focus 0,3 --json

Every live variant makes fresh model-specific discovery. Sweeps require the model/local/server encoder identities to remain constant across the grid; a change stops with exit 69 and retains completed variants. Comparison profiles keep separate identities and pricing. One input budget and overall deadline cover preparation, discovery and every variant's accuracy, warmup and uncached measurement phases. Accuracy may reuse an identical raw request under its exact model/encoder identity; changed packing/questions/context cannot reuse that entry. Combine-only variants may reuse identical chunk responses, then recompute their distinct derived answers. Warmup and latency always bypass cache.
