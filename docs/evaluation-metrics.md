# Evaluation metric calculations

`loupe-core::task_metrics` calculates typed, serializable reports from labeled observations and validated System One answers. It supports noul/Choice/Score classification, reference probability parity, retrieval ID sets and exact timing summaries. These are pure calculations; the separate evaluator must select the fixed split, pin the full run identity and measure actual uncached inference. Calculating a metric does not accept a baseline.

Each scalar is `{value, support, undefined}`. Defined values have a finite number and null `undefined`; missing values have null `value` and an explicit reason. No missing value is converted to zero or passed off as a successful gate. The report records total cases, point/ambiguous labels, accepted decisions, all declared per-label counts, Brier scale and calibration kind.

Classification inputs require unique nonempty case IDs, labels matching the question's declared options/levels and valid actual answer distributions. Raw rounded probabilities are used without normalization, and confidence is recomputed from them. Choice uses sorted-key argmax, including uncertain ties. Noul applies the actual threshold/margin; threshold equality is yes. Score retains the API's issued expected score for ordinal error and uses probability argmax for class-label correctness. Report generation never invents a missing prediction.

Accuracy includes all forced decisions, including uncertain ones. Coverage is the fraction accepted by the actual policy, and selective accuracy is correctness among accepted decisions. An empty accepted set has undefined selective accuracy. Confidence curves replace the policy's min-confidence cutoff with each requested diagnostic cutoff while retaining margin, gap and Choice tie rules; their cutoffs must be unique, increasing and within [0,1]. Noul curves add a diagnostic confidence cutoff to its existing margin, without introducing an inapplicable runtime flag.

Per-label precision is TP / predicted, recall is TP / support, and F1 is 2TP / (predicted + support). Zero denominators remain undefined. A class with true examples but no predictions has F1 zero; a class with neither is undefined. Macro-F1 averages the complete declared class set and remains undefined if any class F1 is undefined, making missing class coverage visible. Noul's standalone F1 selects the positive label. These count formulas and denominator conditions follow the [scikit-learn metric reference](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_fscore_support.html), with Loupe's explicit null/reason policy.

Noul AUROC uses p(true), independently of the policy threshold. Sorting scores and grouping ties computes the positive-negative ranking statistic, with half credit for ties. Both positive and negative examples are required. Confidence, thresholded labels and uncertain omission never replace the underlying probability scores. See the [ROC-AUC reference](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html).

Brier is mean (p(true) - y)^2 for noul, marked `binary`. Choice/Score use the sum of squared errors over the full one-hot option vector, marked `multiclass`, including two-option Choice/Score questions. This keeps question-type scales explicit rather than inferring a scale from an observed label subset. The formulas are documented in the [Brier reference](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.brier_score_loss.html). Reported four-decimal probability rounding remains visible in the calculated result.

Reliability uses ten fixed, right-closed bins: [0,0.1], (0.1,0.2], ..., (0.9,1]. Each row records count, mean predicted value and mean observed outcome; empty rows have null means. Noul uses p(true) and observed positive frequency. Choice/Score use maximum option probability and argmax correctness, marked `top-label`. ECE is the sum of each bin's absolute predicted/observed difference weighted by its share of the point-label cases. The top-label construction follows [Guo et al.](https://proceedings.mlr.press/v70/guo17a/guo17a.pdf); the binary positive-probability variant is explicitly distinguished. Changing a noul threshold changes decision accuracy without redefining its Brier, AUROC or probability calibration.

Score labels can be a single level or an inclusive [low,high] interval. Accuracy accepts an argmax within that set. Ordinal error uses the issued score's minimum distance to the interval, with zero error inside it; within-one accepts minimum distance <=1. The report also supplies minimum/maximum mean absolute-error bounds over possible interval targets. Thus interval MAE is a lower bound, accompanied by its upper bound, rather than an invented midpoint. Non-degenerate intervals are excluded from point-label confusion, Brier and ECE, and their count remains visible. A zero-width interval is a point label. If every score label is ambiguous, point-label metrics are undefined with `no-point-labels`.

Parity validates reference/actual answers against the same question, compares every option probability, and reports maximum absolute error, micro-mean absolute error and per-field argmax agreement. Its counts identify cases, fields and option probabilities, so larger option sets' contribution to the micro mean is explicit. Noul argmax uses the 0.5 yes tie rule; Choice ties use sorted keys and Score ties use numeric level order. Parity does not ratify a quantization tolerance or disguise one served build as another.

Retrieval compares unique ID sets and reports exact-match rate plus micro precision, recall and F1. Empty expected/selected sets match exactly, while their undefined precision/recall/F1 denominators remain visible. It rejects duplicate IDs instead of allowing repeated selections to inflate counts. Source offsets, gating and actual retrieval inference remain responsibilities of the later selection commands.

Timing uses exact nearest-rank p50/p95 from completed latency samples. Throughput is completed original units divided by measured elapsed seconds; zero elapsed time makes it undefined. Empty latency samples have undefined percentiles. The evaluator must identify what each measured sample represents, exclude warmup from measured samples and use uncached inference. HTTP attempts, retries, tokens, prices and GPU-attributed work retain their separate existing accounting.
