# External uncertainty decisions

`--on-uncertain fallback` resolves an uncertain Noul, Choice or Score using a trusted shell command. It covers `is`, `keep`, `drop`, `tag`, `route`, `rate`, `sort`, `count`, `on`, `join`, finite/streaming `dedupe`, `find`, `pick` and `extract`. Raw API, token-plan, feature and factor commands reject process fallback with exit 64. Other `--on-uncertain` output actions remain inapplicable to `is` and `count`; a fallback resolves their decision before the test or histogram.

```sh
loupe --profile server drop 'Does this explicitly mention ALPHA?' \
  --margin 0.1 --on-uncertain fallback --fallback 'printf no'
```

Commands come from `--fallback` or the explicit top-level `[fallback]` section of trusted CLI configuration. They are never read from a preset. CLI settings override configuration. Configuring a command does not enable it; enablement requires the CLI action or a trusted preset's `policy.on_uncertain = "fallback"`. Fallback flags without that effective action exit 64. Empty/NUL commands and zero timeouts are invalid.

```toml
[fallback]
command = "printf no"
timeout = "30s"
on_error = "uncertain"
```

Each uncertain unit reaches fallback during ordered consumption. Primary commands send original unit bytes, including their terminator, to stdin. `join` and `dedupe` send complete compact pair-state JSON plus LF. Join resolves the match gate first and only then resolves an uncertain score for a certain positive gate; dedupe resolves one Noul per candidate pair. Pair diagnostics are preserved alongside separate external selections. See [join.md](join.md), [dedupe.md](dedupe.md) and [streaming-dedupe.md](streaming-dedupe.md). `LOUPE_QUESTION` is compact canonical JSON for the complete typed question, including criteria; `LOUPE_QUESTION_ID` identifies its field; `LOUPE_ANSWER_JSON` is the unchanged raw answer. Their UTF-8 environment limits are respectively 32,768, 8,192 and 65,536 bytes. Metadata overflow leaves the unit uncertain without launching a child. Existing trigger metadata includes the index, model confidence and uncertainty; units/labels beyond 8 KiB or containing NUL are available through stdin/JSON instead of unsafe environment values.

A successful command prints one case-sensitive `yes`/`no`, an exact declared Choice key, or one finite JSON score number in `0..levels-1`. Fractional expected-score values are permitted. Exact Choice keys preserve significant surrounding spaces; conventional final LF/CRLF and insignificant surrounding whitespace are accepted. Multiple values, undeclared labels, invalid UTF-8, NUL, NaN/infinity and out-of-range scores fail. Stdout and stderr are each drained with a 65,536-byte retained capture; truncated stdout is never accepted as a valid prefix.

`--fallback-timeout` defaults to 30 seconds and is bounded by the overall deadline. The shared trigger executor owns and cleans up the child's process group on success, failure, timeout and cancellation. Fallback is not retried automatically. Nonzero exits, timeouts, invalid output and process/metadata failures warn on stderr and preserve uncertainty. The normal uncertain destination or `--uncertain FILE` then applies. `--on-fallback-error fail` stops with exit 69 after the completed output prefix; the failure remains in recovery provenance. An expired overall deadline is fatal even under the default fallback policy.

The raw model response and its probabilities remain unchanged. Successful JSON output adds `decision = {selected, source:"fallback", confidence:null, uncertain:false}` and a separate `fallback` process outcome. Failed executions use `selected:null` and `uncertain:true`; their raw answer remains available. TSV leaves the resolved external confidence column empty. Filter annotations use `fallback=yes|no` instead of attaching the model's probability to an external label. Trigger JSON keeps the raw model assessment; external action metadata uses `LOUPE_DECISION_SOURCE=fallback` and an empty `LOUPE_CONFIDENCE`.

Selection sends the actual packed request state as compact JSON plus LF, including reference context and the current bracket's candidate evidence. It resolves an uncertain presence gate first. Only a certain positive gate reaches Choice fallback; independent `pick` reaches an uncertain Score only when that candidate is eligible. A Choice child prints exactly one declared candidate ID or `none`. An external bracket carries only its winner, so `-n N` can return fewer than N; no probabilities or extra winners are inferred. Independent mode accepts one numeric score per eligible candidate and ranks those values. `none` yields no span. Failed Choice fallback remains uncertain even when the raw model selected `none`.

Selection JSON retains raw answers and adds per-field `fallback`/`selection_decisions`. An external Choice has `probability:null` and the unchanged raw value in `model_probability`; annotate/TSV leave its probability empty. Independent external scores have `ranking_score` and `score_calculation:"external_score"`, with null external confidence. Earlier bracket outcomes and every raw response remain in history. MCP selection tools do not launch fallback commands.

Fallback results do not enter the model response cache. General recovery persists a separate, synced `fallback` frame after the raw completed result and before output. Selection checkpoints each ordered model response and each completed external head, allowing resume to submit only missing requests and reuse completed children. Resume verifies raw requests/counts/bindings, explicit question order and successful saved stdout. Run identity pins the command, timeout and failure policy. Older selection journals without question-order metadata are refused with exit 65; start a new journal. A crash between a child effect and its durable checkpoint can repeat fallback work. Stdout/uncertainty delivery retains the existing acknowledgement gap. `on --state` guards trigger actions; it does not persist or suppress classification/fallback work.

Summary fields distinguish new logical fallback attempts, the fraction of consumed units with new fallback work (a left record for join, a pair for finite dedupe, an input unit for streaming dedupe, a document for selection), resolved/failed/cancelled attempts, completed elapsed milliseconds and replayed results. External executions never charge Loupe's exact model input-token budget. The label-only protocol cannot report provider usage or prices, so `fallback_cost_usd=unavailable` is reported separately with `fallback_cost_scope=external`. A nested Loupe/provider command can report its own costs through its captured stderr.

Selection ensembles apply fallback to uncertain mean fields, including disagreement-only uncertainty. Each child additionally receives the bounded `LOUPE_ENSEMBLE_JSON` report, with unchanged raw primary `LOUPE_ANSWER_JSON`. Gate order, one external Choice winner per bracket and per-head checkpoints still apply. Independent failed Choice outcomes remain uncertain even when the mean `none` option wins; skipped score heads are never executed. JSON preserves all ensemble reports beside effective external decisions.

Join and finite/streaming dedupe ensembles use the same bounded mean report and unchanged raw metadata. Effective mean uncertainty, including agreement-only uncertainty, determines fallback eligibility. Join resolves the mean match gate before its mean similarity score; diagnostic companions never launch children. Pair head outcomes and agreement thresholds are pinned for recovery. An external decision changes the effective match/edge while every raw/member distribution remains intact.
