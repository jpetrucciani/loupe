# Semantic join

`loupe join LEFT RIGHT --on name,location` loads a finite right-side table and streams left records in source order. It uses the [local blocking index](join-blocking.md), then evaluates each retained candidate pair in its own joint model request. JSONL is the default input and output. CSV/TSV input uses `-I csv|tsv`. One side may be stdin (`-`); both cannot. Default candidate cap is 20. No dependencies were added for this stage.

```sh
loupe --profile server join left.jsonl right.jsonl --on name,location --unmatched both --summary
loupe --profile server join - right.csv -I csv --on name,location --cardinality 1:n -O tsv < left.csv
loupe --profile server join left.jsonl right.jsonl --on name,location --failed join-run.jsonl > matches.jsonl
loupe --profile server join left.jsonl right.jsonl --on name,location --resume join-run.jsonl >> matches.jsonl
```

Every request contains one original left and right record, with stable `L<n>`/`R<n>` source IDs. Default fields are an ordered three-level `similarity` Score, a `same_entity` Noul gate and one field-agreement Noul per configured blocking field (`field_1`, `field_2`, ...). All fields within a pair attend jointly. Different candidates are independent requests; batching transport or concurrency does not combine their model states.

The default Score levels are different entities, ambiguous possible match and clear match. Rank is the normalized weighted mean of returned level probabilities, dividing by their rounded total mass and by the maximum level index. Numerical roundoff at the endpoints is clamped to [0,1]. This `ranking_score` is an expected relevance level, not a probability that the pair matches. The API's raw Score, confidence, legend and probabilities remain unchanged in provenance. The `same_entity` true probability is the separate match gate.

`--ensemble` expands named variants from the pair rubric; see [the example](../examples/join-ensemble.toml). `--min-agreement` overrides the default 100% vote requirement. Mean gate/Score distributions drive eligibility and ranking. Raw `gate`, `score`, `probabilities` and companion diagnostics stay unchanged; `decision.derived` contains mean assessments and `decision.ensembles` retains complete member/mean reports. Variants inherit the base field's policy and all context. Gate-first fallback operates on effective uncertainty and receives the mean report alongside raw metadata. The agreement gate is part of plan/recovery identity; changed-gate resume is refused.

A certain negative gate rejects a pair even if its Score confidence is uncertain. Otherwise gate or Score uncertainty follows `--on-uncertain drop|keep|fail|stderr|fallback`, default drop. Keep allows a provisional uncertain match; drop/stderr exclude it, and fail exits 3 before assigning or emitting that left record. Threshold equality is yes; strict distance below margin is uncertain. `-t/--threshold` and `--margin` apply only to `same_entity`; `--min-confidence` and `--min-gap` apply only to `similarity`, using locally computed maximum probability/gap. Companion decisions have their own preset policies and do not veto the gate. A companion may still affect primary answers through joint attention. `--why` prints pair scores, gate probabilities, eligibility, uncertainty and companion assessments; fatal uncertainty retains raw answers in diagnostics and the journal. Quiet suppresses diagnostics.

`--on-uncertain fallback --fallback COMMAND` resolves uncertain pair heads in candidate order. It resolves `same_entity` first. Only a certain positive gate reaches an uncertain `similarity` fallback; a negative or unresolved gate skips score fallback. Diagnostic companions never launch fallback. Stdin is the complete compact pair-state JSON followed by LF, including both original records and stable `L<n>`/`R<n>` IDs. `LOUPE_QUESTION_ID` distinguishes the two heads, with the shared typed-question/raw-answer environment protocol. This differs from primary unit commands, which pass original input bytes. Commands come only from the CLI or trusted top-level `[fallback]` configuration. A trusted rubric may enable the action but cannot supply executable commands.

The gate command prints `yes` or `no`; the score command prints a finite number in the declared level range. An external score is divided by the maximum level to produce `ranking_score`. A successful gate alone does not resolve score uncertainty. Failures warn and exclude the pair unless `--on-fallback-error fail` makes them fatal with exit 69. `--fallback-timeout` and the overall deadline bound each child. Neither fallback work nor its unknown external cost charges the model input-token budget.

JSON retains original gate/score assessments and distributions in `decision`, with successful external selections in `decision.overrides`. Each attempted head also has `fallback.<field>.{execution,decision}`, where the external decision has `source:"fallback"` and `confidence:null`. Matches and rejected evaluated pairs both retain this provenance. TSV keeps its five columns and uses the effective ranking score. Every completed fallback head is synced to the existing join journal before the next head, assignment or output. Resume validates/reuses successful and failed outcomes without another child, including a successful gate followed by a fatal score failure. The command/timeout/failure policy bind resume. A crash after a child effect but before its checkpoint can repeat that child; stdout retains its acknowledgement gap. See [fallback.md](fallback.md).

`-f FILE` or `-p NAME` supplies a trusted multi-question rubric. It must contain `similarity` with at least two ordered Score levels and a `same_entity` Noul. All additional fields must be Nouls. The regular preset trust, argument/env/file template and context permissions apply. Declared `signals` append their own Noul heads and policies. Context reaches every field. The entire ordered schema is counted and cached as one request. Choice companions, missing primary fields, invalid policies and incompatible splitting/combine/window policies are errors. Classification calibration pins are refused because they do not establish pair calibration; a plain full-model identity requirement is checked against fresh discovery. Pair calibration/held-out quality remain separate work.

`--cardinality` controls greedy assignment:

| Mode | Per arriving left record | Right reuse |
| --- | --- | --- |
| `1:1` (default) | Highest-ranked eligible available pair, with right-source-order ties. | Once. |
| `1:n` | All eligible available pairs, in rank order with source-order ties. | Once. |
| `n:m` | All eligible pairs, in rank order with source-order ties. | Allowed across left records. |

Already assigned right records are excluded **before** retaining the top K blocked candidates, so they do not exhaust the cap or consume new model work. Assignment is per arriving left record, rather than a global score ordering. Earlier input can claim a record that a later input would match more strongly. Reversing left input can change the result. The command does not maximize global matching score or merge matched entities transitively.

Default JSON output emits one `matched` object per left record with at least one match. It contains `index`, original left `unit`/`location`, ranked `matches`, complete `evaluated_pairs`, `cardinality` and blocking counts (`eligible_records`, `unavailable_records`). Each match retains the original right index/unit/location, ranking score, local decision, model and cache status. Each evaluated pair, including rejected candidates, retains pair ID, blocking evidence, complete request/question order/counts, raw API response/cache status and derived decision. Gate/Score assessments and separate companion assessments are explicit. Full evidence keeps distributions in their actual per-pair context.

`--unmatched left|right|both` adds unmatched left rows in source order and unmatched right rows after left EOF. Bare `--unmatched` means both. Left rows have empty `matches` and retain completed pair evidence; right rows contain a null left and original right record. Unmatched right means never assigned, rather than merely not considered. A nonempty output exits 0; no output exits 1. `--json` is an explicit default-output shorthand. Other JSON output modes have their own command shapes.

`-O tsv` emits five escaped columns: left index, right index, six-decimal ranking score, compact original left JSON and compact original right JSON. Unmatched sides have empty columns; retained failures put `error` in the right-index column and the message in the final column. Backslashes, tabs, CR and LF are escaped. Plain/annotate/CSV output is exit 64. `--dry-run` always emits local candidates plus complete pair request plans/counts/question order as JSONL, sends no inference, and does not assign predicted matches. It rejects journals and keep-going flags. Planning requests can fail exact preflight, including oversized pair schemas/records.

All pair plans for a left record are checked before its first submission. Each pair remains a whole structured record; records never split. Shared request timeouts/retries, exact per-attempt budgets and fresh-discovery cache rules apply. `--strict` makes count/usage mismatches fatal. `--budget` is a hard verified Clef input-token cap; estimate-only hosted counts remain estimates. Pairs for one left record run with configured concurrency, preserving bounded state and collecting submitted results before selecting. Left records are assigned/output in input order. Overall deadlines and signals cancel the run, including idle input reads; already flushed output remains the prefix.

Fatal unit failures leave earlier completed rows flushed. `--keep-going --on-error drop|keep|fail` applies to recoverable unit preflight/inference failures. Keep emits an `error` row with the original left record and empty matches; drop omits it. Input-reader errors, budgets, explicit uncertainty failure and expired deadlines remain fatal. Failure output does not claim a match or reuse a partial ranking. Summary units count left records, while attempts/latency/usage count submitted pair requests. Uncertainty counts pair decisions in completed rows, or the causal fatal uncertain pair. No GPU-pass or calibrated-quality claim is inferred from those counters.

`--failed FILE` uses the durable general journal with original source admissions, full pair plans and incremental saved pair responses. A left result becomes ready only after all required pairs and assignment complete. `--resume FILE` validates the complete right-index/run identity and all previously admitted left records before new inference or output. Completed source fingerprints must match at EOF. It reconstructs prior right claims, reuses saved complete/partial responses and emits only unfinished left rows. A fully completed resume emits nothing and can use budget 0. Fatal uncertainty can replay the same saved answers and exit without another request. Changed source/schema/policy/model/encoder/output identities are refused. Full live identity is still unavailable on the legacy server service, so cache is disabled and model consistency beyond reported identity is not qualified.

EOF unmatched-right output uses increasing journal checkpoints after each flushed row. Clean resume skips acknowledged right rows too. Like the general stdout journal, a crash between flushing an external output row and its acknowledgement can duplicate that row. This does not claim transactional stdout delivery. Journals refuse input/stdout aliases, unsafe redirected artifacts and competing writers through the shared store. Raw pair states and responses persist in requested private files; use the existing failure/recovery privacy and ownership rules.

Memory consists of the fully loaded right index and assignment sets, one bounded left-reader channel, the current left record and at most K pair plans/responses/decisions/results. It grows with right data and individual record size, rather than left stream lifetime. Exact preflight retains K pair states; full JSON provenance and progress snapshots copy bounded current-row data. Disk journals grow with input length and incremental response snapshots. Local blocking still traverses the right marker array per query; the cap limits candidate/model work, not every local comparison. Named input files and stdin use background readers so the asynchronous deadline/signal handler remains responsive.

Qualification covers five mathematical pair/assignment tests using captured actual distributions, cap-before-exclusion and filesystem checkpoint tests, four offline real-process contracts and three server integrations. Tests demonstrate all cardinalities, raw probability/count provenance, source-order sensitivity, retained uncertainty, budget-limited prefix continuation, input refusal and inference-free completed/fatal replay. Captured CLI probes also cover TSV, retained oversized-record errors, trusted template/context/signal rubrics and clean replay. Three native control captures verify an idle stdin deadline, actual SIGTERM and journal/input alias refusal without inference. Initial test failures used an incorrect count-field name; the encoder uses `input_tokens`, and corrected assertions pass. Held-out blocking recall, pair quality, assignment metrics, full live identity/cache, refreshed release packages and other target platforms remain open.
