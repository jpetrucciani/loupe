# Durable trigger claims and source cursors

```sh
journalctl -fu md-feed -o cat --cursor-file "$HOME/.local/state/md-feed.cursor" \
  | loupe on -p severity --when page --exec 'ntfy pub oncall "$LOUPE_UNIT"' \
      --when ticket --append "$HOME/triage/tickets.log" \
      --state "$HOME/.local/state/loupe-alerts.redb" --dedupe-window 10m
```

`--state FILE` persists fired content/action claims. With an explicit dedupe window they expire, including wall-clock downtime between runs. Without a window, claims are permanent for the lifetime of that state file. This is an at-most-once attempt boundary per rendered comparison content and declared action, even if a child fails or cannot start. Actions never retry. A durable claim commits before an exec launch or append. A crash between claim and effect can lose the action; reopening suppresses it. Removing/changing the state file intentionally creates a new boundary. There is no exactly-once effect guarantee.

The state uses transactional redb with immediate durability, an exclusive writer, mode 0600 creation and an 8 MiB page cache. Permanent claims grow on disk with distinct content/actions, with no history-sized in-memory set. Window expiry has a disk index, pruned in batches of at most 1,024 keys before admission; default capacity is 65,536 live claims, configurable with `--max-fired`. Unexpired-capacity overflow fails 65. State is a regular single-link file with no final symlink, distinct from named inputs/stdin/stdout and append destinations. Dry-run creates no state or append files.

State binds the effective question document/order, reader policy, thresholds, uncertainty action, ordered exec/append declarations, working directory and configured backend/encoder identity. Changed policies/actions/window/capacity require a separate state file and otherwise fail 65. Credentials, output formatting, budgets and source progress are not state keys. The configured model identity scopes these claims; they are not a raw-response cache. Cache still requires fresh authoritative discovery. Claims survive a server build update under the same configured trigger contract. Units are classified again on source replay, and submitted attempts still consume budget; successful classification does not imply an action fired. Suppressed action results contain `suppressed=true`, and a run with no new effects exits 1.

During a run, a wall-clock anchor plus monotonic elapsed time determines expiry. A restart includes real downtime. Backwards wall-clock movement relative to the last recorded claim check fails 65, retaining claims. Expiry equality admits a fresh claim. Content hashes exclude neighbor context and whole-file paths in the same way as local repeat suppression. Declared action ordinal separates actions; input unit indices/cursors do not.

`journalctl --cursor-file` persists journal source progress. Use separate cursor and Loupe state files. A clean journal restart starts after its saved record; removing the cursor replays source records while existing Loupe claims still suppress previously claimed content/actions. Cursor advancement belongs to journalctl and can precede Loupe classification or effects. The two files have no shared transaction, so a crash can also lose unprocessed source records. If loss-free source delivery is required, use a durable upstream queue rather than treating this pipe as one. `loupe --failed/--resume` filter journals are inapplicable to `on`.

Local qualification kills real writer processes before/after claim commit and after a file effect, then verifies rollback or suppression. Actual saved server decisions drive a real child exec through fresh/reopened claims. Tests cover permanent claims, per-action separation, exact expiry/capacity/pruning, changed identity, backwards clocks, locks, symlinks, hardlinks, protected inputs and CLI dry-run/initialization/aliases. A real local journal cursor probe independently proves read, resume with zero repeated records and intentional reset/replay; private log contents are neither retained nor sent to the model.
