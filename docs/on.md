# Streaming triggers

`loupe on` classifies each input unit with one Noul or Choice primary and runs declared actions in CLI order. It streams without a daemon. All commands come from explicit CLI flags; project presets supply trusted questions/context, never executable commands.

```sh
loupe --profile server on 'Does this report an outage?' -t 0.8 --when yes --exec 'notify "$LOUPE_UNIT"'
loupe --profile server on -p severity --when page --exec 'notify "$LOUPE_UNIT"' --when ticket --append tickets.log --dedupe-window 10m
loupe --profile server on -p severity --when page --exec 'notify "$LOUPE_UNIT"' --json --exec-timeout 5s
```

Each `--when` starts a group containing following `--exec`/`--append` flags, ending at the next `--when`. Every group needs an action. Multiple actions in a group run in declaration order. Noul selectors are `yes`, `no`, `uncertain`; Choice selectors are declared keys or `uncertain`. Choice keys cannot use reserved `uncertain`. Threshold/margin apply to Nouls; confidence/gap apply to Choice. Score primaries are invalid. An explicit uncertain selector can fire on the uncertain bucket. Other selectors suppress uncertain decisions by default; `--on-uncertain keep` allows the underlying selected value, stderr warns, and fail exits 3 before actions.

Exec launches one `sh -c COMMAND` per matching unit with original raw bytes on stdin. Environment includes `LOUPE_INDEX`, `LOUPE_CONFIDENCE`, `LOUPE_UNCERTAIN` and bounded `LOUPE_LABEL`. `LOUPE_UNIT` contains unit text up to 8 KiB without NUL; otherwise it is omitted and `LOUPE_UNIT_IN_STDIN_ONLY=true`. Raw stdin remains available in every case. Unit values are passed through stdin/environment, rather than interpolated into the shell command.

`--exec-timeout` defaults to 30s and includes input/output handling; an overall `--deadline` can shorten it. The child owns a process group. Non-reaping exit observation retains ownership until group cleanup, so timeout, cancellation and background descendants are handled before direct-child reap. Reap/output cleanup allows at most one additional second. Explicitly detached descendants leave that group; inherited open output pipes still cannot extend the I/O deadline. Exec actions are never retried, including nonzero exits. Child stdout/stderr are drained concurrently with stdin; each capture retains at most 64 KiB plus total-byte/truncation counts. Diagnostics contain action outcome, original exit code/signal, timeout and any input-write error. Exit status controls action success; a command may deliberately ignore stdin.

Append writes original unit bytes, preserving CRLF/NUL and structured rows. CSV/TSV headers are written only when the destination is empty, and multiple source files require identical headers. Destinations must be regular, single-link files with no final symlink, distinct from named inputs/stdin/stdout. A writer holds the file lock during the session, and successful writes are synced. Parent directories must exist. Dry-run opens no destinations, runs no children and makes no inference calls.

Nonzero/timeout/append failures are logged, and later declared actions/input units continue. Any action failure produces final exit 69. Successful action execution exits 0; no fired actions exits 1. Classification/input/policy failures stop processing, preserving already completed effects and flushed JSON rows. Common whole-unit readers, original record projections/context, schema preflight, exact per-attempt budgets, retries and fresh discovery/cache rules apply to classification. Model retries do not repeat actions.

`--dedupe-window D` suppresses identical rendered comparison content per action until its monotonic expiry. Neighbor context and whole-file path are excluded from that content hash, while remaining in model requests. Expired claims are removed. `--max-fired` defaults to 65,536 live claims and requires a dedupe window; overflow exits 65 instead of silently shortening history. Without `--state`, a fresh invocation has empty history and every occurrence may fire when no window is set. With `--state FILE`, claims persist before effects; explicit windows expire across downtime, and claims are permanent without a window. The [state and source cursor contract](on-state.md) documents policy identity, storage, crash gaps and journald integration.

Default stdout is empty; action diagnostics and captured child output go to stderr. `--json` emits one object per completed input decision with `index`, original `unit`, raw primary `answer`, `model`, `cached`, derived `label`/assessment, ordered action results/suppression, requested signals, full request/counts/response and source location. Dry-run emits full request/counts/question order and the declared action plan, without predicting results. Non-JSON formatting modes other than plain are invalid. Splitting/focus/truncation/non-unit packing, keep-going, uncertain-file and generic filter `--failed`/`--resume` are currently inapplicable; source restart progress will use an external cursor, while durable action claims use `--state`.

Qualification uses real child/process groups, cancellation, file appends/aliases, parser order and actual server Noul/Choice decisions. Durable storage has real writer-crash, expiry/capacity, source-protection and saved-server-decision/child-effect checks; local journald cursors have independent real read/resume/reset proof. Fresh combined server/state runtime, held-out trigger quality, full live identity/cache and refreshed native release artifacts remain open.
