# File route recovery protocol

`loupe route QUESTION -c page,ticket --out DIR` classifies ordered units and appends them to declared, sanitized label files. `--truncate` is a boolean route reset, distinct from text commands' `--truncate head|tail|middle`. `--resume DIR/.loupe-route.jsonl` replays the last file run after validating its configuration and original input prefix. `--dry-run` prints shared request plans and conditional destinations without creating files or executing commands.

Plain output preserves original bytes, including CRLF/NUL and unterminated units. Annotate/TSV/JSON formats go to the selected destinations; JSON keeps the shared five-field unit shape. CSV/TSV plain destinations include one original header, checked against existing data, and require a final delimiter when appending to a nonempty destination. Incompatible headers fail without appending the new unit. Normal route stdout is empty; process commands can produce their own stdout.

Uncertainty follows the shared keep/drop/fail/stderr policy. Explicit `--uncertain DIR/uncertain` captures original bytes through the journal regardless of the main output format; route's uncertainty file is confined to that reserved filename. `--on-uncertain keep` uses the uncertain label under the selected output format. A fatal uncertainty decision stops before a route append. Omitted decisions remain in the journal, and resume retains the no-delivery exit result when every decision was omitted.

One writer holds an advisory lock on the actual output-directory inode. Every open destination retains that ownership. Final root symlinks are rejected, including paths ending in `/` or `/.`; flat label and artifact opens use `openat` against the held descriptor with `NOFOLLOW`. Existing symlinks, multiple hard links, directories, FIFOs and devices fail with exit 74. New directories use mode 0700 and files use 0600, subject to umask. Declared label sanitization rejects collisions, undeclared answers and artifact names. Renaming/replacing the configured root path cannot redirect the held descriptor to a different directory. Other writers must respect this ownership; the lock is advisory.

The journal is `.loupe-route.journal`, version 1, checksummed JSONL. Each durable frame is one of:

| Frame | Meaning |
| --- | --- |
| `begin` | Monotonically numbered run, immutable run identity and declared-label snapshot for recovery across later append runs. |
| `prepare` | Next sequence, original source index/unit hash, chained input-prefix hash, declared label, exact UTF-8 output payload, and optional destination name/device/inode/start/full-prefix hash. |
| `commit` | Matching run/sequence and checksum of the prepared frame. |
| `finish` | EOF at the committed sequence and input-prefix hash. |

Before modifying a destination, create/fsync its file and directory entry when needed, then append/fsync the prepare. Write the payload at its recorded offset and fsync the destination before appending/fsyncing commit. Append the derived manifest row and fsync it. A failure after prepare poisons that writer; it must reopen rather than continue over an unresolved append. A decision with no output still gets prepare/commit with an empty payload and no target, so omitted uncertainty does not lose resume progress.

On reopen, scan the journal sequentially and validate its frame checksums, run/sequence grammar, increasing source indices and input-prefix chain. Hash each destination's preexisting prefix and compare every recorded payload byte range. After validating all committed destinations, check exact final sizes, allowing only the final pending append to be partially present. A conflicting prefix, range, inode, missing file or unrecorded suffix is an error, preserving the conflicting bytes. A torn final journal frame without its newline is removed and synced; complete malformed/incompatible frames are errors and are retained.

For a valid interrupted append, verify that any existing suffix exactly matches the recorded payload prefix. Write only the missing suffix, fsync the output and durably commit. This is repeatable if recovery itself crashes. Build `.loupe-route.manifest.tmp` from all committed entries, fsync it, rename over `.loupe-route.jsonl` within the held directory, then fsync the directory. The old manifest can be missing, torn or stale; regular owned manifests are derived state. Invalid symlink/hard-link artifacts are rejected. Neither manifest contents nor an input unit's byte length are used to infer that an unrecorded append happened.

Manifest rows include `run`, `sequence`, `index`, original `label`, `unit_hash`, `prefix_hash`, optional `target`, `payload_bytes` and `payload_hash`. A target includes the safe filename, device/inode, starting offset and checksum of all prior bytes. Keeping payloads in the journal enables recovery at the cost of duplicated output storage. Memory is proportional to the owned label files across the directory's history plus the largest unit/frame and fixed-size read buffers; the journal is never loaded as a collection of all units. Recovery time is proportional to journal and recorded destination bytes.

The CLI supplies a hash covering effective questions/policy/preset, reader/source configuration, packing/combine/view, encoder/tokenizer and available authoritative model identity, excluding credentials, token budgets, deadlines, concurrency, pricing, and the resume/reset switches. Effective server ceilings remain part of the identity. Resume requires that identity to match. Before allowing new appends, it consumes and compares each recorded source index/unit hash. EOF before that complete prefix is exit 65. A finished run accepts matching replay only; extending it is exit 65. An explicit new append run gets a new run number and preserves prior bytes. Unit identities hash the raw bytes, parsed state/subject, header and source location. Matching recorded decisions are skipped before packing/inference; unrecorded units are evaluated afresh under the configured pack/view. This validates the recorded prefix of a named file or live stdin, rather than inventing a hash of future stream content. Unavailable authoritative identity is recorded as unavailable and never enables cache access. A newly available or changed full identity changes the run hash; live full-identity integration remains a separate gate.

Real tests use temporary files and child processes killed with SIGKILL at eight append boundaries and eight recovery/publication boundaries. They cover a second crash during recovery, partial UTF-8 payloads, original CRLF/NUL bytes, retained preexisting data, torn journal cuts, removed/torn manifests, inode replacement, changed prefixes/suffixes, early EOF, mismatched input, label-bounded state and competing writers. This is Linux process-crash evidence plus explicit fsync ordering, not a hardware power-loss experiment or native macOS qualification. File recovery gives no idempotency guarantee for external process side effects.

## Recoverable reset

`--truncate` first checks input/destination inode aliases, including stdin and historical label files, before journal repair or reset. Ownership inspection never repairs a torn frame. Current declared label files, historical label snapshots/targets and the journal/manifest are owned reset targets. Unrelated files are preserved. A reset explicitly discards owned prior output, including preexisting bytes in those label files.

Before clearing any target, write a checksummed version-1 intent to `.loupe-route.reset.tmp`, fsync it, rename it to `.loupe-route.reset.json` and fsync the directory. The intent contains each owned target's safe name or fixed artifact kind, device/inode, length and full content hash. Recovery validates every target as the recorded original bytes or an already-cleared empty file, then truncates/fsyncs each one. It removes the completed intent and fsyncs the directory. A restart resolves this intent before reading the append journal, so clearing the journal halfway through a reset cannot restore old manifest entries or output. Changed/missing inodes or conflicting bytes fail without clearing remaining targets. The next run starts at run 1.

Actual SIGKILL tests cover eight reset boundaries, followed by a fresh reset with changed labels and new output. Additional tests prove conflict preservation and input-inode protection. Complete corrupt reset intents fail with exit 74. The directory lock covers the entire reset.

## Process destinations

`--to LABEL=COMMAND` overrides that label's file destination, or supplies it when no `--out` is given. Original declared keys and their unambiguous sanitized names are accepted; reserved none/uncertain names are allowed. Without `--out`, every emitting criterion needs a command. Commands come from CLI arguments, are never logged, and are launched lazily once per label through `sh -c`. Units stream to persistent stdin; children inherit stdout/stderr. CSV/TSV plain streams get one original header. Empty/duplicate/undeclared commands are exit 64.

`--to-timeout` defaults to 30 seconds for each stdin write and the shared EOF shutdown interval; `--deadline` also bounds these waits. Close all pipes before waiting for child exits. Nonzero exits, broken stdin, spawn errors and timeouts are exit 69 without child retries. Active, unreaped child groups are terminated on fatal/cancelled shutdown. SIGINT/SIGTERM retain exit 130/143 and interrupt child shutdown promptly. External process costs and side effects remain outside the model token ledger and file idempotency contract.

A mixed file/process run records process decisions as having no recoverable file payload. `--resume` with process destinations is exit 64, and switching a previous process run into file-only resume changes its run identity. Callers cannot infer successful external effects from the file manifest. `--uncertain FILE` conflicts with a process override for uncertain.

Six real server tests cover append/reset, zero-token replay, changed/short/extended input, changed policy, repaired failed suffixes, durable CSV headers, raw uncertainty capture under JSON output, joint-window JSON shapes, persistent process delivery, nonzero child exit, and SIGTERM descendant cleanup. Offline tests exercise real filesystem aliases and process timeouts without an HTTP replacement. General failure artifacts and keep-going scheduling are separate TODO items.
