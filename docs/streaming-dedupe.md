# Streaming dedupe

`loupe dedupe --window N` or `--window-time DURATION` uses greedy keep-first matching against emitted representatives. It emits a new representative as soon as its comparisons finish, before EOF. A dropped unit never enters history and cannot bridge existing representatives or become a later representative. Results deliberately differ from [finite transitive clustering](dedupe.md).

```sh
loupe --profile server dedupe --window 100 < incidents.txt
loupe --profile server dedupe 'Do these records describe the same incident?' --window-time 10m --index-capacity 2000 --json < stream.txt
loupe --profile server dedupe -f pair-question.toml --window 100 -I jsonl --field id --summary < events.jsonl
loupe --profile server dedupe --window 20 --max-candidates 5 --dry-run < sample.txt
```

Question/input grammar, trusted presets, Noul/signal policy, original records, projections, selected columns and context follow finite dedupe. First is the only representative rule; `last` and `longest` are exit 64. The two horizon flags conflict. Whole-pair splitting, focus, truncation, non-unit packing, uncertain-file and keep-going flags remain invalid. `--max-pairs` is finite-only. Choice/Score confidence/gap flags do not apply to the Noul predicate.

| Option | Default | Contract |
| --- | --- | --- |
| `--window N` | none | Compare with representatives from the previous N physical input positions. Skipped blanks and dropped units advance the horizon. |
| `--window-time D` | none | Expire at age greater than or equal to D, measured by monotonic time at decision admission. D must be positive. |
| `--index-capacity N` | 1024 | Time-window limit on live representatives. It is invalid without `--window-time`. |
| `--max-index-bytes N` | 67,108,864 | Maximum sum of serialized retained Units, including original state, raw bytes, subject, context and provenance. |
| `--max-candidates N` | 20 | Maximum retained LSH candidates considered per unit, earliest representative first. |

For `--window N`, age equality remains eligible, so N prior positions plus the current unit can coexist after a successful new representative. At most N+1 entries and 8(N+1) band postings remain; stale entries are removed before the next lookup. File boundaries do not reset history, and indices continue across files. Context starts fresh per source. Time uses decision admission after reading/tokenizer initialization, rather than an event's embedded timestamp or reader-thread arrival time. The history is sampled once per decision; model latency then contributes to age at the next admission. Restart persistence is not implied.

Capacity and byte overflow are exit 65 before emitting the overflowing representative. Already emitted output stays flushed. Unexpired history is never silently evicted to satisfy capacity, because that would shorten the requested horizon. Expiry removes original Units, every band posting and empty posting keys. Current retained/peak bytes and entry counts, band counts/postings, capacity and total expired entries appear as `dedupe_history` in successful summaries and per-row JSON/dry-run diagnostics.

Blocking renders the comparison state, normalizes Unicode lowercase/alphanumeric words, and forms a unique token set. Neighbor context and whole-file paths are excluded from blocking, but remain in model pair states. It uses the same reproducible 64-projection/eight-band MinHash as join. Representatives sharing at least one band are eligible. Candidate IDs are sorted by original source order and capped; there is no all-history semantic fallback. LSH misses and a cap can therefore miss semantic duplicates. Empty token sets have no candidates. These approximate candidate semantics are explicit and need separate held-out recall qualification.

Each candidate gets one joint primary Noul/signals request with original left/right records and stable source IDs. Exact counts, complete question preflight, attempts/retries, deadlines and fresh cache controls apply. The first accepted candidate suppresses the unit; later candidates are not submitted. Uncertain defaults to adding no duplicate edge; keep suppresses against that provisional match, stderr retains the new representative with a diagnostic, and fail exits 3 before emitting that unit. A representative with no candidates must fit the minimum whole-pair prompt too. No-candidate units require no inference. Verbose level two preserves assessed pair raw answers and local policy in stderr; requested `--why` adds declared signals. The legacy server service still lacks full discovery identity, so cache remains disabled.

`--on-uncertain fallback` resolves each uncertain candidate Noul in candidate order. As in finite dedupe, trusted CLI/config commands receive full compact pair-state JSON plus LF and complete typed-question/raw-answer environment metadata. An external `yes` suppresses the new unit against that representative; `no` continues to the next candidate. A failed command warns and leaves that candidate uncertain, adding no duplicate edge; `--on-fallback-error fail` exits 69 before emitting the affected unit, preserving the completed prefix. `--fallback-timeout` and the overall deadline bound owned child groups.

Each completed fallback outcome is saved in the pending candidate progress before later candidates or output. Partial resume validates/replays it without another child or model request; completed unit snapshots reuse the original row and window decision. Commands/timeouts/failure policy bind resume. Pair JSON keeps raw `assessment` and `response`, with separate external `decision` (`source:"fallback"`, null confidence) and `fallback` outcome. Dropped units still have this evidence in a requested journal, while stdout emits representatives only. External costs do not charge the model-token budget. The child-effect/checkpoint and stdout acknowledgement crash gaps remain explicit. See [fallback.md](fallback.md).

Plain output preserves original representative bytes and NUL/CRLF delimiters. CSV/TSV input emits its original header once and requires equal headers across files. Annotate prefixes `representative=<index>` plus a tab. TSV has four columns: representative index, `first`, eligible candidate count and escaped text. JSONL emits only representatives: `index`, original `unit`/`location`, `mode=streaming`, `keep=first`, `candidate_scope=retained_lsh`, capped candidates plus eligible count, expired IDs, complete evaluated pair requests/counts/responses/assessments and current history statistics. It does not claim final cluster membership, since later units are suppressed without retroactive output edits.

`--dry-run` emits one plan per unit, retains every unit as a prospective representative and labels the population `all_prior_units_assumed_representatives`. Its future candidate population can differ from an inferred run, where duplicates disappear. It is useful for cost/state diagnostics, rather than a promise of the exact later inference graph. It performs no model requests. Summary units count input decisions; attempts/usage count submitted candidate pairs.

Resident state consists of bounded representatives/raw records and band postings, capped current-row provenance, one pending reader channel slot, the reader's current unit/parser buffers/context and the pinned tokenizer/backend. There is no history of dropped units or all prior candidate results. The retained byte limit measures serialized data, not allocator overhead or the current unit. Individual oversized records can still consume parsing space before rejection. Work per unit includes tokenization/MinHash plus lookup and up to K model calls; limits bound retained lifetime state, rather than claiming a constant-time semantic filter.

`--failed FILE` uses the existing checksummed JSONL journal and its disposable disk-backed index with a fixed 8 MiB cache. Admissions preserve original Units, positions and context; recorded EOF also preserves full source byte fingerprints. Every successful pair is saved before continuing. Each completed unit saves a bounded snapshot of live representatives/admission times, cumulative expiry/peak counters, its output decision and raw row provenance before stdout delivery. Snapshot restore rebuilds only live LSH postings and validates configured limits, source/time order and counters. Disk usage grows with recorded input and snapshot size; resident journal bookkeeping and current-frame memory do not retain all past units.

`--resume FILE` rereads and validates the admitted source prefix before releasing any saved/new work; an already recorded EOF must also match byte fingerprints. It restores saved window state, skips acknowledged output, reuses partial candidate responses, and re-emits completed-but-unacknowledged rows without inference. Changed source Units, effective question/policy/model/encoder/reader/output identities are refused. CSV headers are not repeated. A fully completed budget-zero resume emits nothing, makes no inference requests and leaves the journal unchanged. Budgets apply to newly submitted attempts in this invocation. Idle input remains cancellable.

Unfinished requests retain their original admission time and candidate population, including on a later resume. Once pending work completes, newly admitted time-window work includes elapsed wall-clock downtime and then advances using a fresh monotonic anchor. Backward wall clocks are refused for time-window continuation; unit windows depend only on source positions. A fresh invocation without `--resume` starts with empty history. There remains a stdout flush/acknowledgement crash gap: a delivered but unacknowledged row can repeat after a crash. The journal does not claim transactional delivery to arbitrary external stdout consumers. Existing single-writer, private-file, alias and torn-tail protections apply.

Qualification includes direct expiry/removal/cap/byte/snapshot tests over 10,000 arrivals, real pre-EOF/time-expiry process tests, actual server unit/uncertainty/recovery decisions and a finite-versus-streaming bridge fixture. A separate Linux producer/consumer probe measures live entries/postings and `/proc` RSS over 10,000 arrivals with durable journals enabled, followed by a complete budget-zero replay. Another probe assumes every unit is retained in dry-run. Both exercise bounded lifetime state. Held-out LSH recall/duplicate quality, current native release artifacts and other platform runtime checks remain open.
